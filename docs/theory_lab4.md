## 1. Частоты в изображении

Изображение можно рассматривать как сигнал яркости I(x, y).

- **Низкие частоты** — медленные, плавные изменения яркости: однотонные области, градиенты неба, общее освещение.
- **Высокие частоты** — резкие изменения на коротком расстоянии: границы объектов, мелкие детали, текстура, шум.

**Фильтр низких частот (low-pass)** сглаживает изображение: оставляет плавную составляющую и подавляет детали и шум. Это размытие.
**Фильтр высоких частот (high-pass)** делает наоборот: убирает плавную составляющую и оставляет только перепады яркости.

Отсюда простейший способ получить ВЧ-фильтр — вычесть из изображения его размытую версию:

```
ВЧ = ИСХ − РАЗМ          (всё изображение = низкие частоты + высокие частоты)
```

## 2. Свёртка

### 2.1. Определение

Свёртка изображения I с ядром (матрицей) K размера n×n:

```
          a     a
R(x, y) = Σ     Σ   K(u, v) · I(x − u, y − v),      a = n div 2
         u=−a  v=−a
```

Каждый пиксель результата — взвешенная сумма пикселей его окрестности n×n, веса берутся из ядра.

**Свёртка и корреляция.** В корреляции стоит `I(x + u, y + v)`: ядро просто накладывается на окно. В свёртке ядро предварительно отражается по обеим осям (поворот на 180°).
Для симметричных ядер (усреднение, Гаусс, Лаплас) разницы нет. Для несимметричных (Собель, тиснение) знак результата меняется на противоположный.
В программе реализована именно свёртка: в `convolve` берётся элемент `kernel[kh−1−i][kw−1−j]`.

### 2.2. Края изображения

У пикселей на краю часть окрестности выходит за изображение. Варианты:
- дополнить нулями — на краях появляется тёмная рамка;
- **повторить крайний пиксель** (используется в программе, `pad_edge`) — рамки нет;
- отразить изображение зеркально;
- не обрабатывать края (результат меньше исходного на n−1).

### 2.3. Нормализация (масштабный коэффициент)

Если сумма элементов ядра S ≠ 1, средняя яркость изображения умножится на S. Например, ядро из девяти единиц делает картинку в 9 раз ярче.
Поэтому ядро делят на масштабный коэффициент — **сумму элементов** S:

```
R = (1 / S) · (K * I)
```

После этого однотонная область остаётся той же яркости. Галочка «Нормализация» включает это деление.
Если S = 0 (Собель, Превитт, Лаплас), делить нельзя. Такие ядра на однотонной области и должны давать 0 — они реагируют только на перепады. Программа в этом случае деление пропускает и пишет об этом в строке состояния.

> В задании сказано «обычно, среднее в матрице». Для усреднения 3×3 из единиц среднее равно 1, и деление на него ничего не даёт. Поэтому делим на сумму = среднее · n².

### 2.4. Отрицательные значения: +128 и модуль

Ядра с отрицательными элементами дают отрицательные отклики. Например, Собель X на перепаде «светлое → тёмное» даёт минус, на «тёмное → светлое» — плюс. Пиксель хранит 0…255, поэтому отрицательные значения при обрезке до 0 пропадают.

| Способ | Формула | Как выглядит | Что теряется |
|---|---|---|---|
| Обрезка | max(0, min(255, R)) | чёрный фон, видна только половина границ | все отрицательные отклики |
| **+128** | R + 128 | серый фон, границы светлые и тёмные | значения за пределами ±128 обрезаются |
| **По модулю** | \|R\| | чёрный фон, светлые все границы | знак (направление перепада) |
| Растяжение | (R − min) · 255 / (max − min) | серый фон, весь диапазон виден | абсолютный масштаб |

Серые картинки на странице Википедии про оператор Собеля получены с +128, чёрные — взятием по модулю.

### 2.5. Вычисления с плавающей точкой

Свёртка считается во `float32`: ядра бывают дробными (Гаусс, 1/9 для усреднения), а промежуточные суммы — отрицательными или больше 255. Округление и обрезка до 0…255 выполняются один раз, в самом конце (`to_uint8`). Если округлять на каждом шаге, ошибки накапливаются.

### 2.6. Сепарабельность и быстродействие

Ядро **сепарабельно**, если его можно записать как произведение столбца на строку: K = v · vᵀ. Например:

```
1 2 1     1
2 4 2  =  2  ·  [1 2 1]
1 2 1     1
```

Тогда свёртку n×n можно заменить двумя одномерными: сначала по строкам ядром [1 2 1], затем по столбцам. Число умножений на пиксель падает с n² до 2n: для 7×7 это 49 → 14.
Усреднение и Гаусс сепарабельны, поэтому размытие в программе делается так (`convolve_separable`).

Вторая оптимизация — порядок циклов. Наивно перебирать все пиксели, а внутри все элементы ядра, на Python очень медленно (миллионы итераций). В `convolve` наоборот: цикл идёт по n² элементам ядра, и на каждом шаге ко всему результату прибавляется сдвинутое изображение, умноженное на коэффициент. Результат тот же, но цикл Python выполняется n² раз, а не h·w·n².

## 3. Размытие

### 3.1. Усреднение (box filter)

Все веса одинаковые и равны 1/n². Каждый пиксель заменяется средним по окну n×n.
Минусы: на границах появляются «ступеньки» — все соседи в окне весят одинаково, близкие и дальние. В частотной области у такого фильтра есть боковые лепестки, поэтому часть высоких частот проходит.

### 3.2. Фильтр Гаусса

Веса задаются двумерной функцией Гаусса:

```
G(u, v) = 1 / (2πσ²) · exp(−(u² + v²) / (2σ²))
```

- Чем ближе сосед к центру, тем больше его вес. Размытие получается мягким, без артефактов.
- **σ** задаёт силу размытия: чем σ больше, тем сильнее размытие.
- **Правило 3σ**: за пределами ±3σ функция почти ноль, поэтому размер ядра берут n ≈ 6σ + 1 (`gauss_size`).
- После вычисления веса делятся на их сумму, чтобы сумма была ровно 1: обрезанный Гаусс не нормирован.
- Гаусс сепарабелен: G(u, v) = g(u) · g(v).
- В частотной области фильтр Гаусса — тоже Гаусс, без боковых лепестков, поэтому высокие частоты подавляются плавно.

## 4. High-pass фильтр: ВЧ = ИСХ − РАЗМ · c

```
ВЧ(x, y) = ИСХ(x, y) − c · РАЗМ(x, y)
```

### 4.1. Смысл параметра c

| c | Результат |
|---|---|
| c = 0 | исходное изображение без изменений |
| 0 < c < 1 | исходное с подчёркнутыми деталями (часть низких частот сохраняется) |
| **c = 1** | чистые высокие частоты: однотонные области → 0, остаются границы и текстура |
| c > 1 | низкие частоты вычитаются «с избытком», изображение становится негативным, детали поверх |

При c = 1 средняя яркость результата ≈ 0. Это значит, что примерно половина значений отрицательная.

### 4.2. Проблема отрицательной яркости

На границе «светлое | тёмное» размытое значение лежит между уровнями. Поэтому со светлой стороны ИСХ − РАЗМ > 0, а с тёмной < 0. Если просто обрезать до 0, тёмная половина каждой границы пропадёт. Решения (выпадающий список в программе) — те же, что в п. 2.4:
- **+128** — ноль переходит в серый, плюс светлее, минус темнее (стандартный вид ВЧ-изображения);
- **по модулю** — обе стороны границы светлые на чёрном фоне;
- **растяжение min..max** — весь реальный диапазон отображается в 0…255;
- обрезка — для сравнения, показывает, что именно теряется.

### 4.3. Связь с повышением резкости

Unsharp masking: `РЕЗКОЕ = ИСХ + k · (ИСХ − РАЗМ)` — к изображению добавляются его же высокие частоты.
То же самое одним ядром — матрица «Резкость» (тождественное − Лаплас 4 соседа):

```
 0 −1  0
−1  5 −1
 0 −1  0
```

Аналогично матрица «Высокие частоты 3×3» (8 в центре, −1 вокруг) — это 9 · (тождественное − усреднение 3×3), то есть ИСХ − РАЗМ одним ядром.

## 5. Выделение границ: оператор Собеля (и Превитта)

### 5.1. Градиент

Граница — место, где яркость резко меняется. Скорость изменения описывает **градиент**:

```
∇I = (∂I/∂x, ∂I/∂y)
|∇I| = sqrt(Gx² + Gy²)          — сила перепада
θ = atan2(Gy, Gx)               — направление (перпендикулярно границе)
```

### 5.2. Ядра

Производная приближается разностью соседей. Собель дополнительно сглаживает поперёк направления производной весами 1-2-1, поэтому он устойчивее к шуму:

```
Собель X        Собель Y        Превитт X       Превитт Y
−1  0  1        −1 −2 −1        −1  0  1        −1 −1 −1
−2  0  2         0  0  0        −1  0  1         0  0  0
−1  0  1         1  2  1        −1  0  1         1  1  1
```

Собель X = [1 2 1]ᵀ · [−1 0 1]: сглаживание по вертикали, умноженное на производную по горизонтали.
Gx реагирует на **вертикальные** границы, Gy — на **горизонтальные**.

### 5.3. Алгоритм в программе (`edges`)

1. Перевести изображение в яркость: Y = 0.299 R + 0.587 G + 0.114 B.
2. (Опционально) размыть Гауссом σ, чтобы шум не давал ложных границ.
3. Gx = свёртка с Собель X, Gy = свёртка с Собель Y.
4. |∇I| = sqrt(Gx² + Gy²), отмасштабировать в 0…255.
5. (Опционально) порог: пиксель — граница, если |∇I| ≥ T. Результат — бинарная карта.

Выбор порога: маленький T даёт много шума и текстуры, большой — разрывы в слабых границах.
Улучшение — детектор Кэнни: подавление немаксимумов вдоль градиента (тонкие линии) и два порога с гистерезисом.

## 6. Выделение углов: детектор Харриса

### 6.1. Идея

Возьмём маленькое окно и сдвинем его на (Δx, Δy). Изменение содержимого окна:

```
E(Δx, Δy) = Σ w(x, y) · [I(x + Δx, y + Δy) − I(x, y)]²
```

- **Однородная область**: при любом сдвиге E мало.
- **Граница**: E велико при сдвиге поперёк границы и мало при сдвиге вдоль неё.
- **Угол**: E велико при сдвиге в любом направлении.

### 6.2. Матрица структуры

Разложение Тейлора даёт E(Δx, Δy) ≈ [Δx Δy] · M · [Δx Δy]ᵀ, где

```
M = Σ w · | Ix²    Ix·Iy |
          | Ix·Iy  Iy²   |
```

Ix, Iy — производные (Собель), w — окно Гаусса с параметром σ.
Собственные значения λ1, λ2 матрицы M показывают, насколько сильно меняется яркость в двух главных направлениях:

| λ1 | λ2 | Что это |
|---|---|---|
| мало | мало | однородная область |
| велико | мало | граница |
| велико | велико | **угол** |

### 6.3. Отклик Харриса

Чтобы не искать собственные значения явно, используют:

```
R = det(M) − k · trace(M)² = λ1·λ2 − k·(λ1 + λ2)²,      k ≈ 0.04…0.06
```

- R > 0 и большое — угол;
- R < 0 — граница;
- |R| мало — однородная область.

Чем больше k, тем меньше найдено углов: детектор строже относится к точкам, похожим на границу.

### 6.4. Алгоритм в программе (`harris`)

1. Яркость Y, производные Ix, Iy — оператор Собеля.
2. Ix², Iy², Ix·Iy, сглаженные окном Гаусса σ (сепарабельная свёртка).
3. R = Ixx·Iyy − Ixy² − k·(Ixx + Iyy)².
4. Порог: R > доля · max(R) (по умолчанию 0.01).
5. **Подавление немаксимумов**: оставить только точки, где R — максимум в окне радиуса r (`max_filter`). Иначе вокруг каждого угла найдётся «пятно» из десятков точек.
6. Нарисовать крестики (`draw_crosses`).

Свойства: детектор Харриса инвариантен к повороту (собственные значения от поворота не зависят) и частично устойчив к изменению освещения (порог относительный). К масштабу он не инвариантен: при увеличении угол становится похож на границу.

## 7. Справочник стандартных ядер (вкладка «Свёртка»)

| Ядро | Сумма | Нормализация | +128 | Назначение |
|---|---|---|---|---|
| Тождественное 3×3 | 1 | — | — | проверка: результат = исходное |
| Усреднение 3×3 / 5×5 | 9 / 25 | да | — | размытие |
| Гаусс 3×3 / 5×5 | 16 / 256 | да | — | мягкое размытие |
| Резкость | 1 | — | — | повышение резкости |

| Превитт X / Y | 0 | — | да | производная по x / y |
| Тиснение | 1 | — | — | эффект рельефа |

## 8. Вопросы для защиты

**Почему у Собеля нормализация «не работает»?** Сумма элементов равна 0, на однотонной области ядро даёт 0. Делить на 0 нельзя, и это не нужно: Собель измеряет перепад, а не яркость.

**Чем свёртка отличается от корреляции?** В свёртке ядро отражается на 180°. Для симметричных ядер результат одинаковый, для Собеля меняется знак.

**Зачем +128?** Чтобы сохранить отрицательные отклики: 0 становится серым, отрицательные значения — темнее серого.

**Почему Гаусс лучше усреднения?** Веса плавно убывают от центра, поэтому нет ступенчатых артефактов. Частотная характеристика без боковых лепестков, высокие частоты подавляются плавно.

**Что даёт c в формуле ВЧ?** Сколько низких частот вычитать. c = 1 — чистые высокие частоты, c < 1 — резкость, c > 1 — инверсия с деталями.

**Почему перед Собелем размывают?** Производная усиливает шум, потому что шум — высокие частоты. Размытие подавляет шум, но сохраняет крупные перепады.

**Зачем подавление немаксимумов в Харрисе?** R велико не в одной точке, а в небольшой области вокруг угла. Оставляем только локальный максимум — один угол = одна точка.

**Как ускорена программа?** Цикл по элементам ядра вместо цикла по пикселям: изображение сдвигается и умножается на коэффициент целиком. Размытие раскладывается на две одномерные свёртки (2n вместо n²). Изображение 1024×1024 обрабатывается за десятки миллисекунд.
